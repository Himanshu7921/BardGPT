# Security Policy

## 1. Supported Versions

The following table indicates which versions of BardGPT are currently supported with security updates:

| Version | Supported |
|--------|-----------|
| 1.x.x  | ✓ Active support |
| 0.x.x  | ✗ No longer supported |

Older versions may continue to work, but they will not receive patches for security vulnerabilities.

---

## 2. Reporting a Vulnerability

If you discover a security vulnerability in BardGPT, please report it **privately**.

Do **not** publicly disclose the issue until it has been reviewed and resolved.

To report a vulnerability, contact:

**Maintainer:** Himanshu Singh  
**Email:** himanshusr451tehs@gmail.com

Your report should include:

- A clear description of the vulnerability  
- Steps to reproduce (if applicable)  
- Potential impact  
- Any suggested fixes or patches  

You will receive a timely response acknowledging your report.

---

## 3. Disclosure Process

Once a vulnerability is reported:

1. The maintainer will investigate and verify the issue.
2. A fix will be developed, reviewed, and validated.
3. A patched release will be issued.
4. A public disclosure will be made *only after* users have access to the fix.

You will be credited for the discovery unless you request anonymity.

---

## 4. General Guidelines

To help maintain a secure project:

- Avoid exposing sensitive information in logs, checkpoints, or example code.
- Validate all external input before passing it into model code.
- Follow secure development practices when using this project in downstream applications.
- Do not use BardGPT in environments requiring strict security guarantees without further auditing.

---

Thank you for helping to keep BardGPT secure.
